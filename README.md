# Лабораторные S3 и MLflow

В `01_s3.ipynb` выполнены все 7 задач, в `02_mlflow.ipynb` — все 8 задач.
Исходные задания и учебные примеры сохранены. Решения находятся непосредственно
под условиями; выводы, графики и проверки сохраняются в ноутбуках.

## Локальный запуск

Выберите в Jupyter/PyCharm интерпретатор `.venv/Scripts/python.exe` и выполните
ячейки сверху вниз. По умолчанию оба ноутбука используют `LAB_MODE=local`.
Установка библиотек из PowerShell:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для выполнения обоих ноутбуков с сохранением результатов:

```powershell
.venv\Scripts\python.exe run_notebooks.py
```

Этот скрипт всегда проверяет локальный режим. Для серверного режима запускайте
ноутбуки через Jupyter/PyCharm с переменными окружения ниже.

S3 работает через Moto: настоящий интерфейс boto3, объекты в памяти ядра.
При перезапуске ядра или повторном выполнении настройки бакет очищается.
Скачанные файлы находятся в `lab_artifacts/s3/`. Проверка политики доступа
учебного сервера и открытие HTTP-ссылки S3 остаются для серверного запуска:
локальный эмулятор в памяти не предоставляет веб-сервер. График прочитан
из S3 и отображён прямо в ноутбуке; ссылка подписывается на 600 секунд.

MLflow работает с настоящей базой SQLite `lab_artifacts/mlflow/mlflow.db`.
Модели и артефакты хранятся в файловом хранилище MLflow (каталог `mlruns/`).
Для локального веб-интерфейса выполните из корня проекта:

```powershell
.venv\Scripts\python.exe -m mlflow ui --backend-store-uri "sqlite:///lab_artifacts/mlflow/mlflow.db" --port 5000
```

Откройте [MLflow](http://127.0.0.1:5000), эксперимент `local_student_cancer`:

1. Выберите три запуска `cmp_*` последнего сравнения и нажмите **Compare**.
2. В `sgd_40_epochs` посмотрите `train_accuracy` и `val_accuracy` по шагам 0–39.
3. В **Models** откройте `local_student_cancer_model`: версии и alias `champion`.
4. У `parallel_cancer` разверните дочерние запуски: их должно быть три.

Повторное выполнение добавляет запуски и версии. Сравнение трёх моделей
ограничено уникальным `comparison_id` текущего выполнения. Ворота качества
обновляют `champion` только при строго большем ROC-AUC кандидата.

## Переход на учебный сервер

Перезапустите ядра, чтобы остановить Moto и очистить настройки предыдущего
режима. Перед запуском Jupyter/PyCharm задайте переменные окружения PowerShell:

```powershell
$env:LAB_MODE = "remote"
$env:S3_ENDPOINT_URL = "http://10.162.1.86:9000"
$env:S3_PUBLIC_ENDPOINT_URL = "http://10.162.1.86:9000"
$env:S3_USER = "userN" # замените на выданный логин
$env:MLFLOW_TRACKING_URI = "http://10.162.1.86:5000"
$env:MLFLOW_TRACKING_USERNAME = "userN"
$env:MLFLOW_UI_URL = "http://10.162.1.86:5000"
```

Пароли ноутбуки запросят через `getpass`. Также поддерживаются `S3_PASSWORD`
и `MLFLOW_TRACKING_PASSWORD`, если они уже безопасно заданы в окружении.
Не записывайте пароли в код или сохранённые выводы ячеек.
При запуске Jupyter внутри учебной сети можно задать внутренние адреса
`http://s3:9000` и `http://mlflow:5000`; публичные адреса для браузера
задаются отдельно. Имя бакета берётся из `S3_USER`, имена экспериментов
и моделей — из `MLFLOW_TRACKING_USERNAME`.

Серверный запуск заново загрузит данные и создаст эксперименты; локальная
база и бакет автоматически на сервер не переносятся. Для возвращения к
локальному режиму задайте `$env:LAB_MODE = "local"` и перезапустите ядра.

API сохранения моделей и связь дочерних запусков проверялись по
[документации MLflow sklearn](https://mlflow.org/docs/latest/api_reference/python_api/mlflow.sklearn.html)
и [MLflow tracking](https://mlflow.org/docs/latest/api_reference/python_api/mlflow.html).
